# Feature guide

**English** · [한국어](FEATURES.ko.md) · [Back to README](../README.md)

| Capability | Details |
|---|---|
| **SSH terminal** | Full terminal powered by SwiftTerm; in-process libssh2 engine for stable, fast connections. The login banner / MOTD stays visible: the helper line ServerDock injects after login (for folder tracking) is hidden by filtering its echo, not by clearing the screen |
| **SFTP browsing** | Upload / download / rename / chmod, resumable transfers, concurrent queue, in-app remote code editing |
| **Remote Desktop** | Add either Windows RDP (embedded FreeRDP, full-color graphics, keyboard and clipboard) or VNC (RFB framebuffer, keyboard and mouse) hosts from the Remote Desktop panel. VNC defaults to port 5900 and stores its password in Keychain; the VNC form also has an optional **Username** (macOS Screen Sharing needs the Mac account name, other servers only ask for a password). When a saved password is missing or a username is required, the login dialog asks for it and has a **Save these credentials after a successful login** checkbox — the username and password are saved to the host only once the login actually succeeds.. A **viewer toolbar** sits above the screen: Control / View only (stops sending mouse and keyboard), Send Key Combination (Ctrl-Alt-Del, Alt-Tab, Esc, Tab, Windows/Command key), Screenshot (copy or save as PNG), Zoom out / Actual size / Zoom in / Fit to window (⌥+scroll pans a zoomed view), Resize Window to Remote Screen, Full Screen, and Disconnect / Reconnect |
| **Port forwarding** | A dedicated activity-bar workspace collects all servers’ rules with search, server filters and start/stop controls. Pick a server first, enter its remote port, and use the same local port by default or choose a different one. Includes database/web port presets and advanced address settings. Supports local (-L), remote (-R) and dynamic SOCKS (-D) tunnels running in the background |
| **Server import / export** | File › Import Servers / Export Servers, or open **Hosts › List** to use the host manager. JSON includes SSH, RDP and VNC connection settings, notes, colors and sections (including empty sections). Import keeps existing entries and skips duplicate profiles; legacy `hosts.json` is also accepted. Passwords and private keys are excluded; select keys and enter passwords again on another Mac. Commands and notes may contain sensitive information, so keep the export private |
| **Host monitoring** | Live CPU / memory / disk / network charts, with system notifications on sustained load. Linux hosts (reads `/proc`); on failure the reason is shown under the status line and logged as `[Monitor] …` in Console.app |
| **Volumes list** | The monitor's Volumes section lists only writable mounts — read-only volumes (Android `/`, `/vendor`, `/apex/*`, macOS sealed system snapshot, squashfs/ISO) are hidden, since they're always ~100% full |
| **Host overview layout** | Top to bottom: a compact hero (name and address, with the Online status and response time at its top right; a one-line system summary — OS, cores, memory, disk (red at ≥90%), GPU, Mac model/chip — with Edit and Connect at the bottom right) → **warnings** (each with a one-click action: disk → Disk Usage analysis of the full mount, password expiry → `passwd`) → **live monitoring** → **Quick Access** tiles (Files · AI Assistant · Space Analyzer · Docker when installed · HTTP Check · Port Forwarding; the Disk tile shows the fullest mount when it is ≥90%) → an auto-wrapping card grid of **Favorites**, **Recent Files** (up to 6 each; click to open) and **Logs** (only the log files you add per server: **+** opens a server file picker like the AI assistant's — browse folders starting at `/var/log`, tick one or more files, or type a path and press Return (a folder opens it, anything else can be added as a file) — then **Add**; click a row to follow it live, ✕ or right-click to remove; stored per host) → notes. The local Mac host keeps its system-app shortcuts as tiles and also gets the Space Analyzer tile and the Favorites, Recent Files and Logs cards (only the Security card is server-only) |
| **Host warnings** | The host overview shows a banner for key issues found by the system probe (Linux): login-account **password expiry** (warning ≤14 days, critical ≤3 days or expired) and account expiry, a writable mount ≥90% full (read-only and virtual filesystems such as Android `/system`·`/apex`, snap squashfs and ISOs are ignored; macOS remote hosts are not checked because reclaimable space can't be read; the local Mac uses Finder's "available for important usage" figure), and reboot-required. Read via `chage -l` etc. for the login user; refreshed with the system info (every 30 min, and once after updating from an older version) |
| **Terminal connection mode** | Pick **Connection Type** at the top of the host form's General tab. **OS SSH** (default): just type an ssh command such as `ssh user@192.0.2.10` (or a `~/.ssh/config` alias) — the terminal runs it as-is through your login shell like iTerm, so ProxyJump / Port / IdentityFile apply. The file browser, monitoring and port forwarding read host, user, port, key and jump host from that command via `ssh -G`. **Local Start Directory** (like iTerm's Initial directory; default Home) sets where the command runs locally — useful for relative `-i ./key` paths; the remote start folder / startup command stay under Initial Options. An optional password/passphrase is typed automatically at the first prompt, and the cwd-tracking hook is injected after login (echo hidden). **Built-in SSH**: the in-app libssh2 connection with the Address / Port / Authentication fields as before. The Mac App Store build always uses Built-in (sandbox) |
| **Jump host (ProxyJump)** | In the host form's Proxy Settings, set **Jump Host** (`user@bastion:22`, comma-separated for multiple hops) to reach servers only reachable through a bastion — the same as `ssh -J`. The engine launches `/usr/bin/ssh -W host:port <jump>` and runs libssh2 over it, so the jump host authenticates with your own `~/.ssh/config` / keys / agent (BatchMode, no prompts). Set the host's own port (e.g. 2222) in the form — `~/.ssh/config` `Port`/`ProxyJump` entries are not auto-imported. The target's host key is trusted on first use (no preflight dialog through a jump) and rejected if it later changes. Overrides the proxy URL |
| **SSH Agent authentication** | In the host form, set **Authentication Method** to **SSH Agent** and choose System ssh-agent (`SSH_AUTH_SOCK`), 1Password or Secretive (detected from their default sockets). The private key stays inside the agent and never passes through ServerDock; the agent may ask you to approve each use (Touch ID etc.). It works for the built-in engine (terminal, files, monitoring, port forwarding, connection test) and, for OS SSH commands, via `IdentityAgent` |
| **SSH key management** | Generate / import ed25519 · RSA in-process — no `ssh-keygen` dependency |
| **SSH Key Manager** | A separate tool (bottom-left activity bar button, next to Settings) that manages real files directly on disk — default `~/.ssh`, or any folder you choose. **Keys tab**: generate / rename / duplicate / delete, edit the public key comment, add/change/remove the private key's passphrase, copy the public/private key or fingerprint, reveal in Finder. **Config tab**: add/edit/delete `Host` blocks in `~/.ssh/config` (a lossless editor that preserves comments and formatting elsewhere in the file) with a live reachability check per host. **Known Hosts tab**: browse `known_hosts` grouped by host and remove entries. A Read-Only Mode toggle blocks all of the above. This is independent of the Keychain-backed "Keys" library above (the `key` icon) — that one stores credentials for ServerDock's own connections; this one edits your actual `~/.ssh` files |
| **Edit as root (sudo)** | When the editor can't open or save a file for lack of permission, use **Open with sudo** / **Save with sudo**. Passwordless sudo is used directly; otherwise you're asked for the sudo password once per server (kept in memory only until the app quits, sent over stdin, never on the command line). Saving writes in place, so the file's owner and mode are kept. Not available when the server's sudoers requires a TTY (`requiretty`) |
| **File panel (right side)** | Whenever an SSH server is active, its remote file tree sits in a panel on the right of the workspace, next to the terminal — connecting a server shows the terminal and the file list together. The tree follows the active terminal's `cd` — it opens the path level by level with a short animation and folds branches it opened earlier (so it doesn't keep growing); the ◎ button in the panel header turns following off/on; click a file to open it in the editor, right-click for file operations. Resize by dragging its left edge, hide/show with ⌥⌘B (or the button in the tab bar) — the choice and width are remembered. It replaces the per-host "Files" tree that used to live in the Hosts sidebar |
| **Server tabs** | Two-level tab bar: the top row has one tab per server (status dot, tab count, unsaved-file dot; local terminals share a "Local" tab), and the row below holds that server's file browser, editors, and overview — that row sits inside the rounded content card (same background and corner radius as the Hosts panel), so the top edges of the sidebar, content and file panel line up. Clicking a server returns to the sub-tab you last used there |
| **Ping list** | Host rows show a latency number only when it is slow (over 100 ms). For all hosts, the small pulse button next to the search box opens a popover listing every host's response time (or Offline); opening it, or its refresh button, re-measures |
| **Server colors** | Every host has a color so you can tell servers apart at a glance. New hosts get one automatically (the least-used color in the palette); change it under **Color** in the host form (10 presets or any custom color), for SSH and RDP hosts alike. It shows as a small stripe on the sidebar row, a tinted server tab with an underline, the server-name pill in the terminal panel header, and the directory icon in the terminal toolbar; the accent color of the server workspace (file browser and editor buttons and selections, terminal toolbar, status bar, file transfers, AI panel, port forwarding, Docker, web tabs) follows the active server's color instead of the app's default blue. Existing hosts are assigned a color on first launch after updating |
| **Editor toolbar** | The buttons above the code editor: **Find** menu (Find ⌘F, or Find and Replace — the bar also has a Find/Replace dropdown at its left), **Word Wrap** toggle, **Font Size** menu (larger / smaller / reset), **Thumbnails** (minimap) toggle, a **⋯ More** menu (copy file path, reload, reveal in the file panel, open the file's folder in a terminal, download, open with the default app or any app that supports the file type, share via the system share sheet), **Save** (⌘S), and a **?** button that opens a popover explaining each one. Word wrap and font size are remembered |
| **Open in other apps / Share** | For any remote file — from the editor's ⋯ menu or a right-click in the file tree or browser: **Open with Default App**, **Open With ▸** (installed apps that handle the file type), and **Share…** (AirDrop, Messages, Mail…). The file is copied to a temporary folder first (the editor uses its current unsaved text); edits made in another app are not uploaded back, and copies older than 24 hours are cleaned up |
| **Connect flow & workspace guide** | Connecting from a host's overview opens its terminal and closes the overview tab, so you land on the terminal with the file panel on the right (like VS Code). Reopen the overview any time from the terminal bar's gauge button, a server's **+** menu, or by clicking the host in the sidebar. The **?** button at the right of the tab bar explains the terminal, file panel, editor, overview, server colors and shortcuts (⌘J, ⌥⌘B, ⌘W) |
| **Favorites** | Pin the folders and files you always look at, per server. They live in the **Favorites** tab of the right-hand file panel (tabs: **Files · Favorites · Recent · Scripts**, each with the full panel height), so right after connecting you're one click from them: click a folder to jump to it in the Files tab's tree (hover for a button that `cd`s the terminal there), click a file to open it in the editor. Add with right-click → **Add to Favorites** on any file or folder, the **★** in the terminal bar (current directory), or the editor's ⋯ menu. Remove from the row's ✕ or right-click. Anything that is in Favorites also shows a small yellow **★** after its name in the file tree, the folder file list and the file browser, so pinned paths stand out. Stored per host in `favorites.json`; deleting a host removes its favorites |
| **Tail (follow a file)** | Right-click a text file in the file panel (or use the editor's ⋯ menu) and choose **Tail (Follow Changes)** to open a live view of `tail -F` (last 200 lines, then new lines as they are written; log rotation is followed). The toolbar has a filter box, pause/resume, auto-scroll, word wrap, copy all and clear; up to 5,000 lines are kept. Text files only: obvious binary types are hidden from the menu, and the server checks the first 4 KB for binary data before starting. Runs over its own SSH connection (or a local process on this Mac) and stops when the tab is closed |
| **Folder disk usage (du)** | Right-click a folder in the file panel and choose **Analyze Disk Usage**. The analysis opens in the editor area (one reusable view per server — picking another folder moves it instead of opening more tabs), and the file panel opens with its collapsed **folder file list** expanded and the folder selected in the tree. The view runs `du` on the server (or this Mac) and lists the folder's items largest first with a bar, percentage and size, plus the folder total. Click a folder to go into it (it is measured again and selected in the tree), a file to open it; use the breadcrumb, Back and Parent buttons to move around, Refresh, and *Stay on one filesystem* (`du -x`, on by default) to skip other mounted disks. Right-click a row to copy its path, reveal it in the tree or open a terminal there. Sizes are disk usage, so they can be a little larger than the byte size of a file. On this Mac, a banner appears when Full Disk Access is missing (protected folders would be skipped) with a button to Privacy & Security; macOS can't grant it for you, and the app must be restarted after you turn it on. Results are cached for 5 minutes per folder and each scan also records sizes three levels down, so back/up/revisits are instant and entering a subfolder shows its folder sizes right away while files fill in; Refresh re-measures |
| **Recent files** | The **Recent** tab of the file panel lists the last 20 files you opened on that server (newest first, per host) so you can jump back in one click. Hover a row to star it into Favorites or remove it; use the Clear History button at the top of the tab. Stored in `recents.json`; deleting a host removes its history |
| **Status bar** | A slim rounded panel under the terminal and file panel for the connected SSH server you're viewing: connection state dot, server name, `user@host`, response time (updated every 30 s), the terminal's current folder (click to copy), the **Git** branch with ahead/behind and changed-file counts when that folder is a repository (click for details; runs read-only `git status`/`git log` on the server every 30 s — turn off in Settings › Terminal › Git Info in Status Bar), the number of active port forwards when present (click to manage), and a **Transfers** button that opens the list of uploads, downloads and other background tasks (with a count badge while some are running). The **Live Stats** toggle at its right end adds live CPU / memory / load / uptime; it's off by default because it keeps one extra background connection to that server while on. Remote desktop (VNC/RDP) tabs show their own status bar: connection state, protocol, address, user, remote screen size, time connected and response time |
| **Folder file list** | In the file panel's **Files** tab, the tree keeps showing everything, and a small auxiliary list underneath shows only the files of the selected folder (or the terminal's current folder), so files are easy to spot when there are many folders. Click a file to open it; right-click for the usual file actions. Drag the divider to resize; collapse it with the panel-header button or by clicking the list's header bar — it then shrinks to just that bar, and clicking the bar again expands it. State and height are remembered |
| **Local host (this Mac)** | Your Mac is a host like any other, pinned at the very top of the Hosts list (not in the App Store sandbox build). Click it to open its overview (system info including Mac model and chip, live monitoring, and quick links to Disk Utility, Activity Monitor and System Information), **Connect** opens a local terminal and closes the overview, and then you get the same workspace as a remote server: the right-hand file panel with this Mac's files (tree, folder file list, Favorites, Recent, Scripts), the editor (open/save local files), the status bar (current folder, Git, Live Stats, transfers) and the terminal toolbar. The file panel's Delete action shows permissions and copies a permanent deletion command for you to review and run in a terminal; it does not move files to the Trash. Port forwarding and the AI chat panel are remote-only. By default the app opens this overview on launch — change it (Welcome Page / Local Overview / New Terminal) in Settings › General › Startup Behavior |
| **Host management** | The **+** at the top of the Hosts sidebar (next to the manage icon) adds a host, and two buttons pinned at the bottom of the sidebar — **Add** (add a host) and **List** (open the management window) — do the same. Add or edit SSH hosts there, import iTerm2 JSON profiles, create and rename sections (including empty ones), reorder sections and hosts, or move hosts between sections. **Duplicate Host** (right-click a host in the sidebar, or the ⋯ menu in the management window) copies a host — SSH or remote desktop, including its connection settings and saved password — as "<name> copy", placed right after the original. Deleting a section moves its hosts to Ungrouped. The nearby manage button opens the same window. The window also controls whether the local host appears in the Hosts list and which page or host overview opens when the app launches. A deleted startup host falls back to the Welcome Page. Reordering works by drag and drop in both the Hosts sidebar and the management window: drag a section header (or drop a section onto any host to move it to that host's section position) to reorder sections, drag a host onto another host to reorder it, or onto a section header to move it into that section (in the management window also onto an empty section) |

| **Welcome screen** | Shown when no host or tab is open: the app icon, name and version (with a Check for Updates link); a **Start** list (Add Host, Open Local Terminal, Import from iTerm2, SSH Key Manager, Settings) next to **Recent Hosts** — the hosts you used last, newest first with how long ago (hosts never opened fill the rest in list order); below, a grid of cards for what the app can do (terminal & files, code editor, live log tail, disk usage analyzer, command toolbox, AI assistant, remote desktop, port forwarding, monitoring, SSH key manager, scripts, favorites & recents, resumable transfers, archive extraction, open with & share, sudo editing, Git status bar, server colors, ping list, local Mac host, privacy mode, terminal panel, image preview, load alerts, iTerm2 import, auto update, English & Korean — trim the list in `WelcomeView.features`) and the key shortcuts (⌘J, ⌥⌘B, ⌘W). On a narrow window the columns stack. The last-used times are kept locally in the app's preferences. The Open Local Terminal row is hidden in the App Store sandbox build |
| **Terminal panel** | VS Code-style: a server's terminals live in a panel at the bottom of the workspace with their own tab strip, below its files/editors. Drag the divider to resize, hide/show with ⌘J (or ⌃\`, or the panel button in the tab bar). A server with only terminals uses the whole workspace for them. Clicking into a terminal or editor makes it the active tab |
| **Terminal toolbar** | A button bar above SSH terminals: current directory (click to copy), upload files here, new file here (opens straight in the editor), scripts menu, **Common Commands** menu, port forwarding, host overview, clear screen, new terminal, and a **?** button that opens a popover explaining what each button does. The **Common Commands** menu groups read-only look-up commands — Files & Folders, Disk Usage, System, Network, Services & Logs, Docker, Git — and commands with options (`ls`, `df`, `du`, `free`, `ps`, `ss`, `find`, `journalctl`…) have a submenu of variants such as `ls -alh` or `df -hT`; choosing one runs it in the current terminal. At the bottom, the **chmod / chown Generator** builds the command from checkboxes (owner/group/others × read/write/execute with the octal value and common presets like 644/755, or user and group names for chown), with recursive, verbose, `sudo` and folder-only execute (`X`) options; **Copy**, **Insert** (types it at the prompt) or **Run** it. Next to it, the **rsync Command Generator** builds an `rsync` command for that terminal's machine — on this machine, *send to another server*, or *fetch from another server* (pick a saved host to fill user/address/port/key, or type them): source and destination, **Preview only (-n) on by default** so nothing changes until you turn it off, archive/verbose/compress/human-readable/itemize, `--partial`, checksum, skip-newer/skip-existing, `--delete` (with a red warning), progress (none / per file / overall), exclude patterns, `--bwlimit`, `-e 'ssh -p … -i …'` and `--rsync-path='sudo rsync'`, with hints such as the trailing-slash rule. Only the command text is generated; Copy, Insert or Run (Run Preview while -n is on) sends it to the terminal Can be turned off in Settings › Terminal. In a Git repository folder an icon-only **Git** button also appears (branch and change count at the top of its menu and in its tooltip, yellow dot when there are changes): read-only commands and fetch / `pull --ff-only` run immediately, while add / commit / push / stash / switch (including picking a branch) are only typed at the prompt for you to review. The ✨ button is the **AI Command Generator**: describe a task, get one editable command with an explanation and a safe/caution/danger rating, then **Insert** (type only), **Run** (risky ones ask twice) or **Copy** — the AI never runs anything itself. It uses the AI Chat provider settings; running a full CLI agent on the server is a link inside the popover |
| **Monitoring** | The Host Overview collects live CPU, memory, disk, network, and load data while that overview is open. Linux and Android hosts use `/proc`; macOS hosts use built-in system tools. It requires an SSH host, a usable credential, and an available network connection. The overview follows the host's color (header, icons, memory/disk/upload bars) and lays the charts out in two columns — CPU · Memory, then Volume · Network — with GPU cards full width below |
| **AI profiles** | Register an AI once and reuse it on every host: a **name**, **which AI** (Claude / ChatGPT), **where it runs** (my Mac / the server, with a plain-language explanation and an Important warning for the Mac mode) and **standing instructions** (a base prompt sent with every question, e.g. "Answer in Korean"). In the AI panel header, pick a saved AI from the dropdown, or choose **Edit This AI…** / **Add AI…**; with nothing registered yet the panel shows an **Add AI** screen. Stored in `aiprofiles.json`; deleting a profile keeps past conversations |
| **AI path picker** | The folder chip in the AI panel header is a button: it opens a server browser (up / home / folder list). **Use this folder** makes the AI work in that folder (highlighted; **Follow terminal** returns to the terminal's current folder — the choice is remembered per host); the **paperclip** on any file or folder attaches it to your next question as a `📎 /path` line (shown as chips above the input, removable, cleared after sending) |
| **AI chat panel** | A conversation panel per host (open it from a server's `+` menu, right-click menu, or the terminal toolbar): register your AIs and switch between them, keep every conversation per host — reopen the panel and you're back in your last conversation; the **✎** button starts a new one without deleting the old, and the **clock** menu lists past conversations (titled by your first question, with date) to reopen and continue or delete (history is saved in `aichat.json`; the single conversation from older versions is migrated automatically) — and send suggested commands to that server's terminal. The text you're typing is kept when you switch tabs. **Enter** sends the message and **Shift+Enter** adds a new line (while a Korean/Japanese/Chinese input method is still composing, Enter only confirms the composition). The location button (with a **?**) opens a plain-language popup explaining both modes — including an **Important** warning that in the Mac mode the AI can run commands on the server by itself with your login account's permissions, while suggested commands in the chat only run when you press **Run in Terminal**. **Run on my Mac** (formerly *Mac → SSH*) is the default (the App Store build defaults to **Run on the server**); it runs a local CLI that connects using the host's SSH settings, or **Run on the server** to run the CLI on the remote host. The Mac mode is available in the direct distribution; the App Store sandbox runs the server mode. Install and sign in to the CLI where it runs. Settings › AI Assistant lets you select a model or use the CLI default |
| **Import from iTerm2** | Restore SSH hosts from an iTerm2 profile JSON export (the import button in the Hosts sidebar). Reads user / host / port (`-p`, `-l`, `-o Port/User/HostName`, `ssh://`), the `-i` identity file, the first Tag as the group, and Initial Text as the initial command; duplicates (same user@host:port) are skipped |
| **Scripts** | Insert or run frequently used commands in one click. Manage them in the **Scripts** tab of the right-hand file panel (search, create, edit, run/insert into the current terminal); with a local terminal active the panel shows only that tab. The same list is also in the left activity bar (the `</>` icon, under RDP), so you can manage scripts without a server open. The terminal bar's scripts menu is still there for quick use. **Clicking a script opens its own tab** (under a *Scripts* chip) with the body, a **Variables** form and run options: pick the terminal to run in (with several terminals open you must choose, so nothing runs on the wrong server), **Run** (sends and presses Return) or **Type only** (types at the prompt for review), optional **Clear screen first**, then **Run / Insert / Copy** with the variables filled in; **Edit**, **Duplicate** and **Delete** are in the header. Variables are `{{name}}`, `{{name=default}}` (default value) or `{{env=dev\|staging\|prod}}` (a choice, first is the default); last-used values are remembered per script and recent values are offered by variable name across scripts. The ▶ button in the list still sends straight away using your default action |
| **Docker management** | A **Docker** tile in the host overview's Quick Access (also in the server tab's right-click menu) — shown only on hosts where `docker` is installed (checked with `command -v docker` each time the overview opens; hidden while unknown or when the host asks for a password every time and none was entered yet) — opens a per-server Docker tab that runs `docker` commands over the existing SSH session — no need to expose the Docker daemon's TCP port. It lists every container (state dot, image, status, CPU, memory, ports; `unhealthy` is highlighted), with search, an All/Running/Stopped filter, sortable columns, and a live refresh every 8 s while the tab is open (toggle **Auto**; **Resources** turns off the `docker stats` call). Select one or more containers to **Start · Stop · Restart · Pause · Kill · Remove**; stopping, restarting, killing and removing always ask for confirmation first, and docker's error output is shown in a banner when something fails. **Logs** opens a live `docker logs -f` view in the log-tail tab (filter, pause, auto-scroll), **Open Shell in Container** runs `docker exec -it … bash||sh` in that server's terminal, and **Inspect** shows `docker inspect` output with a copy button. When Docker can't be used the tab says why instead of showing an empty list: not installed / not on the login PATH, permission denied (with the `docker` group hint and a **sudo** option that uses passwordless `sudo -n`, remembered per server), or the daemon isn't running. Works on the local Mac too |
| **Open web services through a tunnel** | In **Port Forwarding**, **Open Web Service** takes a target (host, port, HTTPS) — with presets for Proxmox VE, Synology DSM, Portainer, Cockpit, Grafana, Jenkins, Prometheus and Kibana — creates a local (-L) tunnel on a free port, waits until it's connected and opens the page in a **web tab** inside the app. A running local rule also gets a globe button (open as HTTP or HTTPS). The web tab has back/forward/reload, an address bar and an *Open in Default Browser* button; it stores no cookies or logins after the app quits, and it accepts self-signed certificates only for the tunnel's own `127.0.0.1` port (typical for Proxmox and NAS admin pages). The tunnel is an ordinary rule in the Port Forwarding list and keeps running after the tab is closed until you stop it there |
| **HTTP Check** | A tool in **Tools › Network** (also the **HTTP Check** tile in Quick Access and the command palette). Enter a URL, pick **This Mac** or a **Server**, GET/HEAD, follow redirects, ignore certificate errors, and see status text, total / connect / first-byte time, size, remote address, redirect target and headers. *Server* runs `curl` over SSH, so it shows whether a service answers from the server's own point of view (e.g. `http://localhost:8080/health`). **Save** keeps an address for the host (shown as chips; right-click a chip to remove) and **Run in Terminal** sends the equivalent `curl` to the host's terminal. Saved addresses are stored per host |
| **Network Tools** | File › Network Tools… (⌥⌘T), the wrench button in the left activity bar, the command palette, and the **Network Tools** tile in the host overview open the tool list. The **wrench** button in the left activity bar opens the **Tools** list in the side panel, split into collapsible sections like the host list — **Manage** (SSH Key Manager), **Network** and **Certificates** (SSL Certificate, Subdomain Finder).
